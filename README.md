# DAMN Unidad IV · Reportes del campus

Ejemplo público de organización del trabajo para Desarrollo de Aplicaciones Móviles Nativas. Todos los datos son ficticios. Este repositorio contiene documentación y acuerdos de clase, no una aplicación ya implementada.

## Objetivo

Registrar un reporte con ubicación y fotografía, enviarlo a una API y consultar su cambio de estado. El cliente puede desarrollarse con KMP y Compose Multiplatform o con Flutter. Los ejemplos Views/XML se analizan por el plan de estudios.

## Trabajo del equipo

[Tablero público](https://github.com/users/gabrielhuav/projects/3) · [Flujo de trabajo](docs/flujo.md) · [Definición de terminado](docs/definicion_de_terminado.md) · [Riesgos](docs/riesgos.md).

Las historias #1, #2 y #3 describen ubicación, API/foto y notificaciones. Están pendientes. Puntos e iteraciones son ejemplos didácticos y no compromisos de entrega del grupo.

## Git y Projects

Git versiona archivos y commits. Projects conserva campos y vistas en GitHub; no se guarda automáticamente dentro de Git. Por ello, los acuerdos y evidencias reproducibles viven en docs/.

## Verificación

El workflow comprueba enlaces relativos de la documentación. Su resultado no demuestra que exista una app móvil ni sustituye las pruebas de sus sensores, API o notificaciones.
